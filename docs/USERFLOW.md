# User Flow: OpenClaw Machines Journey

This document defines the end-to-end user experience for OpenClaw Machines, mapping the user's actions to the underlying technical enablement.

---

## 1. Phase 1: The "Hire" (Machine Creation)
The user transitions from a visitor to a "Manager" of a digital employee.

### User Steps:
1. **SSO Login:** User signs in via Google or GitHub (frictionless).
2. **Account Selection:** User selects their personal or team account.
3. **Machine Creation:** User clicks **[ Create New Machine ]**.
4. **Configuration:** User fills out a single high-fidelity form:
   - **Machine Name:** (e.g., "Jarvis-01").
   - **Sizing:** Selects Small (Free/1GB) or Pro (2GB).
   - **Region:** Picks US, EU, or APAC.
   - **AI Identity:** Pastes their **Anthropic API Key** (or toggles "Use Managed Credits").
   - **Messaging Hub:** Pastes their **Discord Bot Token** (link to @BotFather guide provided).

### Technical Enablement:
- **Backend:** `POST /api/accounts/{id}/machines` creates a database record in the `stopped` state.
- **Scheduler:** Reserved a slot on a shared Host VM but does not boot yet.

---

## 2. Phase 2: The "Move-In" (Provisioning)
The user watches their infrastructure come to life.

### User Steps:
1. **Launch:** User clicks **[ Start Machine ]**.
2. **Progress Observation:** User sees a real-time status bar:
   - *"Allocating isolated KVM hardware..."*
   - *"Injecting secure identity vault..."*
   - *"Waking the agent brain..."*

### Technical Enablement:
- **SSE Stream:** The frontend listens to `GET /api/machines/{id}/progress`.
- **Orchestrator:** Calls `CreateVM` on the Agent. Reflink copies the RootFS instantly.
- **Metadata:** The Agent registers the Discord Token and AI Key in the `.253` metadata service.

---

## 3. Phase 3: The "Handshake" (Pairing)
The secure link between the Agent and the User is established.

### User Steps:
1. **Verification:** User sends a message to the bot on Discord: `Hi`.
2. **Safety Check:** The bot replies on Discord: *"I don't know you yet. Please approve pairing code `🦞-1234` in your dashboard."*
3. **Approval:** User clicks a large **[ Approve Handshake ]** button on the Clara Dashboard.

### Technical Enablement:
- **Handshake UI:** The dashboard polls the Machine's internal health endpoint.
- **Command Proxy:** When clicked, the Backend sends a CLI command (`clawdbot pairing approve`) to the MicroVM via the Agent's control port.

---

## 4. Phase 4: The "Watch" (Live Oversight)
The core visual differentiator of the platform.

### User Steps:
1. **Observation:** User switches to the **"Live Cam"** tab in the dashboard.
2. **Visual Audit:** User watches the agent navigate the web (Zillow, Google, GitHub) in real-time.
3. **Manual Intervention:** If the agent hits a CAPTCHA or Login, the user clicks the stream directly to help the agent pass the blocker.

### Technical Enablement:
- **Visual Proxy:** Agent Proxy (9091) streams JPEG frames from Playwright to a `<canvas>` element via WebSocket.
- **Interactive Overlay:** Mouse/Keyboard events on the canvas are sent back to Playwright's `page.mouse.click()` API.

---

## 5. Phase 5: The "Artifacts" (Work Results)
Viewing the output of the agent's work.

### User Steps:
1. **Result View:** User clicks the **"Output"** tab.
2. **File Browser:** User sees a list of files generated by the agent (e.g., `market-report.csv`, `screenshot.png`).
3. **Download:** User clicks **[ Download as ZIP ]**.

### Technical Enablement:
- **File API:** The `workspace/server` inside the VM serves a directory listing and a dynamic ZIP generator route.

## Required UX Components (The Dashboard)

| Component | Purpose | Supported Interactions |
| :--- | :--- | :--- |
| **Fleet Grid** | Overview of all user machines. | Status badges, Stop/Start toggles. |
| **Log Console** | Real-time agent logic feedback. | Xterm.js streaming logs. |
| **Live Cam** | Visual browser stream. | Click-to-interact, Fullscreen mode. |
| **Secret Vault** | Managed identity storage. | Encrypted fields for tokens/keys. |
| **Handshake Modal** | Security approval. | pairing code display + Approve button. |
| **Artifact Sidebar** | Result management. | Tree view of files + ZIP download. |
