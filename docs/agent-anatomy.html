Anatomy of an OpenClaw Agent

What makes an AI agent tick — Soul, Identity, Brain, Heartbeat, and how multiple agents work together. How to set them up and optimize for cost.

The Big Picture

An OpenClaw gateway runs one or more agents. Each agent is a fully isolated AI assistant with its own soul, identity, brain, workspace, sessions, and credentials. Nothing is shared between agents — they are completely independent.

┌────────────────────────────────────────────────────────────────────────┐ │ OPENCLAW GATEWAY │ │ │ │ ┌─────────────────────────────┐ ┌─────────────────────────────┐ │ │ │ AGENT: "chat" │ │ AGENT: "deep" │ │ │ │ │ │ │ │ │ │ Soul — friendly, │ │ Soul — thorough, │ │ │ │ casual │ │ analytical │ │ │ │ Identity — 💬 Chatty │ │ Identity — 🧠 Deepy │ │ │ │ Brain — Sonnet │ │ Brain — Opus │ │ │ │ Heartbeat — 60s check-in │ │ Heartbeat — 60s check-in│ │ │ │ │ │ │ │ │ │ ┌────────────────────────┐ │ │ ┌────────────────────────┐ │ │ │ │ │ WORKSPACE │ │ │ │ WORKSPACE │ │ │ │ │ │ SOUL.md │ │ │ │ SOUL.md │ │ │ │ │ │ IDENTITY.md │ │ │ │ IDENTITY.md │ │ │ │ │ │ AGENTS.md │ │ │ │ AGENTS.md │ │ │ │ │ │ USER.md │ │ │ │ USER.md │ │ │ │ │ │ TOOLS.md │ │ │ │ TOOLS.md │ │ │ │ │ │ HEARTBEAT.md │ │ │ │ HEARTBEAT.md │ │ │ │ │ │ MEMORY.md + memory/ │ │ │ │ MEMORY.md + memory/ │ │ │ │ │ │ skills/ │ │ │ │ skills/ │ │ │ │ │ └────────────────────────┘ │ │ └────────────────────────┘ │ │ │ │ │ │ │ │ │ │ Sessions — per channel │ │ Sessions — per channel │ │ │ │ Credentials— own API keys │ │ Credentials— own API keys │ │ │ └─────────────────────────────┘ └─────────────────────────────┘ │ │ │ │ ┌────────────────────────────────────────────────────────────────┐ │ │ │ BINDINGS (routing) │ │ │ │ WhatsApp → "chat" │ Telegram → "deep" │ default → "chat" │ │ │ └────────────────────────────────────────────────────────────────┘ │ └────────────────────────────────────────────────────────────────────────┘

Think of each agent like a person:

  • Soul = their values, expertise, and personality
  • Identity = their name, face, and how they present themselves
  • Brain = the AI model — the actual intelligence you're talking to
  • Workspace = their desk — files, notes, tools, and memory
  • Heartbeat = how they stay alive and responsive in long sessions
Key point: Every agent has its own complete set of these components. Agent "chat" can have a casual soul with a cheap brain, while Agent "deep" has an analytical soul with a premium brain. They don't share workspaces, memory, or sessions.

Soul

The agent's personality, expertise, and guiding instructions.

What It Is

The soul is defined in SOUL.md in the agent's workspace. It's the set of instructions that tells the AI model who it is and how it should behave. Every message the agent sends is shaped by its soul.

A soul defines:

  • Role — "You are a senior backend engineer" or "You are a research analyst"
  • Expertise — what domains the agent specializes in
  • Behavior — how it approaches tasks, communicates, and makes decisions
  • Constraints — what it should avoid or be careful about (hard blocks)
  • Style — tone, verbosity, format preferences
Example souls:
  • "You are a meticulous code reviewer. Always check for security vulnerabilities, performance issues, and adherence to the team's style guide. Be direct but constructive."
  • "You are an organizational delegate assistant. Never send external emails without human approval. Never export contact lists or financial records."

Cost Impact

SOUL.md is injected into every turn. It's part of the system prompt, so its content consumes tokens on every single message. Longer soul = more tokens = higher cost.
  • A 200-word soul adds ~300 tokens per message — fractions of a cent, but adds up over thousands of messages.
  • Keep it focused. 200–500 words works better than 2,000+. The model follows clear, short instructions better than vague, long ones.
  • Bootstrap files are capped at 20,000 chars per file and 150,000 chars total across all files.

How to Set Up

Edit SOUL.md in the agent's workspace:

  • OpenClaw CLI: openclaw setup creates default templates, then edit ~/.openclaw/workspace/SOUL.md
  • Per-agent: Each agent has its own workspace, so each has its own SOUL.md
  • OCM: Dashboard → Machine → Agents → "Soul" field (stored in DB, injected into workspace at boot)

Identity

How the agent presents itself — name, emoji, avatar.

What It Is

The identity is defined in IDENTITY.md in the agent's workspace. It controls how the agent appears in the UI and introduces itself in conversation.

  • Name — display name shown in chat (e.g., "Rex", "CodeBot", "Work Assistant")
  • Emoji — visual identifier next to the agent's name
  • Avatar — profile picture URL

When you have multiple agents, identity is how you tell them apart at a glance.

Cost Impact

Minimal. IDENTITY.md is injected into context like other bootstrap files, but it's typically very short (a few lines). The visual elements (emoji, avatar) are metadata with zero token cost.

How to Set Up

  • OpenClaw: Edit ~/.openclaw/workspace/IDENTITY.md
  • Multi-agent config: Set identity in agents.list[]: 
    {
  agents: {
    list: [
      {
        id: "coding",
        name: "CodeBot",
        identity: { name: "CodeBot", emoji: "robot face" },
        workspace: "~/.openclaw/workspace-coding"
      }
    ]
  }
}
  • OCM: Dashboard → Machine → Agents → Name, Emoji, Avatar fields

Brain

The AI model that powers the agent — what you're actually talking to.

What It Is

The brain is the AI model (LLM) that reads your messages, thinks, and responds. When you talk to your agent, you're talking to the brain. It determines:

  • Intelligence — how well the agent understands complex requests
  • Reasoning — how it breaks down problems and decides what to do
  • Quality — how accurate and helpful responses are
  • Speed — how fast the agent responds
  • Cost — how much each interaction costs

Every agent has one primary model. Different agents can use different models — a cheap one for quick tasks, an expensive one for deep work.

How the Brain Relates to Soul

The soul tells the brain what to do. The brain determines how well it can do it.

Soul says...Brain determines...
"Be thorough and cite sources" Can it actually search, find, and synthesize information well?
"Follow our code conventions" Can it read existing code, understand patterns, and apply them?
"Be concise" Can it reason about what's essential vs. what to omit?

A great soul with a weak brain gives you an agent that knows what it should do but can't execute. A great brain with no soul gives you a capable agent that doesn't know what you want.

How the Brain Is Selected

OpenClaw uses a priority chain:

  1. Agent-specific model — set per-agent in agents.list[].model
  2. User's preferred model — set in config or platform overrides
  3. Auto-detect from API keys (BYOK) — Anthropic → Claude, OpenAI → GPT-4o, Google → Gemini
  4. Platform default — falls back to the platform-provided model

Model IDs use provider/model format (e.g., anthropic/claude-sonnet-4-6, openai/gpt-4o).

Cost Impact

The brain is the single largest cost factor. Your model choice creates up to a 100x cost difference.
Model tierExamplesInput costOutput costBest for
Premium Claude Opus, GPT-4o $2.50–15 / 1M tokens $10–75 / 1M tokens Complex reasoning, nuanced writing, difficult code
Standard Claude Sonnet, GPT-4o-mini $0.25–3 / 1M tokens $1–15 / 1M tokens Most tasks — good balance of quality and cost
Budget Gemini Flash, DeepSeek, Claude Haiku $0.01–0.25 / 1M tokens $0.03–1 / 1M tokens Simple tasks, high-volume automation
Platform OCM-provided model Included in plan Included in plan Getting started, no API key needed

Other cost multipliers:

  • Tool use — each tool call is an additional round-trip to the model. 5 tool calls per message ≈ 5x cost.
  • Skills and capabilities — each adds to the system prompt, increasing tokens per message.
  • Conversation length — the model re-reads the entire history on each turn.

How to Set Up

// Per-agent model in openclaw.json
{
  agents: {
    list: [
      {
        id: "chat",
        model: "anthropic/claude-sonnet-4-6",     // standard tier
        workspace: "~/.openclaw/workspace-chat"
      },
      {
        id: "deep",
        model: "anthropic/claude-opus-4-6",        // premium tier
        workspace: "~/.openclaw/workspace-deep"
      }
    ]
  }
}

// Or set a default for all agents
{
  agents: {
    defaults: {
      model: { primary: "anthropic/claude-sonnet-4-6" }
    }
  }
}

OCM: Dashboard → Machine → Agents → Model field, or Machine → Settings → Preferred Model

Heartbeat

How the agent stays alive and responsive during long sessions.

What It Is

The heartbeat has two meanings in OpenClaw:

1. Agent Heartbeat (in-session keep-alive)

Defined in HEARTBEAT.md in the workspace. On a configurable interval, the agent wakes up and calls a small AI model to check if there's anything worth saying — new events, pending tasks, proactive updates, or just an acknowledgment. The model reads the conversation history and HEARTBEAT.md instructions, then decides whether to send a message or stay quiet.

This is not a simple HTTP ping — it's a lightweight AI call every cycle. To keep costs down, OpenClaw supports:

  • Model override — use a cheap/fast model for heartbeats (e.g., Haiku) instead of your main brain
  • Light context mode — sends a trimmed-down system prompt (fewer bootstrap files) to reduce token usage
  • Active hours — only run heartbeats during configured hours, sleep the rest
  • Ack max chars — if the model's response is just a short acknowledgment (e.g., "ok"), skip delivery entirely

2. Host Heartbeat (OCM infrastructure)

In OCM, a separate heartbeat runs at the infrastructure level — the host agent sends a simple HTTP signal to the control plane every 60 seconds, reporting health, IP, version, and VM count. If 3 heartbeats are missed (180 seconds), the host is marked unreachable. This one is just ~200 bytes/minute with no AI model involved.

Cost Impact

Low but not free. Each agent heartbeat cycle makes an AI model call. With a cheap model (Haiku-class) and light context mode, this might be a few hundred tokens per cycle. At a 5-minute interval, that's ~300 calls/day per agent — small but not zero.

The host heartbeat (OCM only) is truly free — just a tiny HTTP POST with no AI tokens.

Cost tip: Set heartbeat.model to a fast, cheap model (e.g., anthropic/claude-haiku-4-5) and enable lightContext: true. This keeps heartbeat costs minimal while still letting the agent proactively check in.

How to Set Up

Agent heartbeat

Edit HEARTBEAT.md in the workspace to define when and how the agent should check in. Then configure heartbeat options in openclaw.json:

{
  "heartbeat": {
    "model": "anthropic/claude-haiku-4-5",   // cheap model for check-ins
    "lightContext": true,                      // trimmed system prompt
    "activeHours": { "start": "08:00", "end": "22:00" },
    "suppressToolErrorWarnings": true
  }
}

Host heartbeat (OCM)

Automatic — starts when the host agent boots. Fixed at 60-second intervals, no configuration needed.

Workspace

The agent's home — files, memory, and skills that define how it operates.

What It Is

Every agent has a workspace — a directory that serves as its working environment. The workspace contains the agent's personality files, memory, tools notes, and skills. It's the agent's "desk."

~/.openclaw/workspace/ (or workspace-<agentId>) ├── AGENTS.md ← operating instructions + memory ├── SOUL.md ← personality, boundaries, tone ├── IDENTITY.md ← name, emoji, vibe ├── USER.md ← who the human is ├── TOOLS.md ← tool usage conventions ├── HEARTBEAT.md ← keep-alive behavior ├── BOOTSTRAP.md ← first-run ritual (deleted after) ├── MEMORY.md ← curated long-term memory ├── memory/ │ ├── 2026-03-28.md ← daily session notes │ └── 2026-03-29.md └── skills/ └── ... ← agent-specific skills

Key point: On the first turn of every session, OpenClaw injects the contents of these bootstrap files directly into the agent's context. They are the source of truth for the agent's personality, instructions, and memory.

Each Agent Gets Its Own Workspace

When running multiple agents, each one has a completely separate workspace. This means:

  • Different SOUL.md → different personalities
  • Different AGENTS.md → different operating instructions
  • Different MEMORY.md → different memories
  • Different skills/ → different capabilities

Agents don't share workspaces. If one agent learns something, the other agents don't know about it unless you explicitly copy the information.

Cost Impact

All bootstrap files are injected every turn. Their combined content counts against your token budget. Keep them concise — especially MEMORY.md, which can grow over time and cause unexpectedly high context usage.

memory/*.md daily files are not injected automatically — they're accessed on demand via memory_search and memory_get tools, so they don't count against the context window unless the model explicitly reads them.

How to Set Up

  • First time: openclaw setup creates the workspace and seeds default templates.
  • Multi-agent: openclaw agents add coding creates a new workspace at ~/.openclaw/workspace-coding
  • Manual: Create the directory and add the .md files yourself.
  • OCM: Workspaces are created automatically per-agent. Soul and instructions are configured in the dashboard.

Multi-Agent: Running Multiple Agents

How to run different agents for different tasks, channels, or people.

Why Multiple Agents?

A single agent works for many people. But there are good reasons to run multiple agents:

  • Different brains for different tasks — a cheap model for quick chats, a premium model for deep work
  • Different personalities — a coding assistant, a research analyst, a family bot
  • Different channels — WhatsApp goes to one agent, Telegram to another
  • Different people — multiple users sharing one server, each with isolated data
  • Different security levels — sandboxed agents with restricted tools vs. full-access agents

How It Works

The OpenClaw gateway can host multiple agents side by side. Each agent is fully isolated:

┌──────────────────────────────────────────────────────────┐ │ OPENCLAW GATEWAY │ │ │ │ ┌─────────────────┐ ┌─────────────────┐ │ │ │ Agent: "chat" │ │ Agent: "deep" │ ... │ │ │ │ │ │ │ │ │ SOUL.md │ │ SOUL.md │ │ │ │ brain: Sonnet │ │ brain: Opus │ │ │ │ workspace/ │ │ workspace/ │ │ │ │ sessions/ │ │ sessions/ │ │ │ │ credentials/ │ │ credentials/ │ │ │ └────────┬────────┘ └────────┬────────┘ │ │ │ │ │ │ ┌────────┴────────────────────┴────────┐ │ │ │ BINDINGS (routing) │ │ │ │ │ │ │ │ WhatsApp → "chat" │ │ │ │ Telegram → "deep" │ │ │ │ Discord #code → "deep" │ │ │ │ everything else → "chat" (default) │ │ │ └──────────────────────────────────────┘ │ └──────────────────────────────────────────────────────────┘

Bindings route incoming messages to the right agent based on channel, account, peer, guild, or other criteria. The most specific match wins.

Single Agent (Default)

With no configuration, OpenClaw runs one agent with agentId: "main":

  • Workspace: ~/.openclaw/workspace
  • Sessions: ~/.openclaw/agents/main/sessions
  • State: ~/.openclaw/agents/main/agent

This is all most people need. You only need multi-agent if you have a specific reason from the list above.

Setting Up Multiple Agents

Step 1: Create agents

openclaw agents add coding
openclaw agents add social

Each gets its own workspace, state directory, and session store.

Step 2: Configure in openclaw.json

{
  agents: {
    list: [
      {
        id: "chat",
        name: "Everyday",
        default: true,
        model: "anthropic/claude-sonnet-4-6",
        workspace: "~/.openclaw/workspace-chat"
      },
      {
        id: "deep",
        name: "Deep Work",
        model: "anthropic/claude-opus-4-6",
        workspace: "~/.openclaw/workspace-deep"
      }
    ]
  },
  bindings: [
    { agentId: "deep", match: { channel: "telegram" } },
    { agentId: "chat", match: { channel: "whatsapp" } }
  ]
}

Step 3: Customize each workspace

Edit each agent's SOUL.md, IDENTITY.md, and other files independently.

Step 4: Verify

openclaw agents list --bindings
openclaw channels status --probe

Sub-Agents and Sessions

Beyond the top-level agents you configure, OpenClaw also runs sub-agent sessions for specific tasks:

Session typeWhat it isSystem prompt
Main session Your primary conversation with the agent (DM, web chat) Full — all bootstrap files, skills, memory, heartbeat
Group session A conversation in a group chat (WhatsApp group, Discord channel) Full — with group chat context added
Sub-agent session A spawned task — the main agent delegates work to a focused sub-session Minimal — only AGENTS.md, TOOLS.md, and workspace context. No skills, memory recall, heartbeat, or self-update.
Cron session A scheduled task that runs automatically on a timer Scoped to the cron job's instructions
Node session A remote worker in a distributed multi-node setup Scoped to the node's role
Why sub-agents use a minimal prompt: Sub-agents are spawned for focused tasks. They don't need skills, memory recall, self-update instructions, or heartbeat — so those sections are stripped out. This keeps context small, reduces cost, and keeps the sub-agent focused.

Putting It Together: Cost Optimization

How the pieces fit and how to spend wisely.

Cost Summary

ComponentCost driverHow to optimize
Soul Injected every turn (constant token cost) Keep SOUL.md under 500 words. Be specific, not verbose.
Identity Small file, minimal tokens Keep IDENTITY.md brief — a few lines.
Brain Largest cost factor — model choice (100x between tiers), tool use, capabilities Use multiple agents with different models. Start with Standard tier.
Workspace files All bootstrap files injected every turn Keep AGENTS.md and MEMORY.md concise. Move details to daily memory files.
Heartbeat Negligible No optimization needed.

Example: Cost-Optimized Multi-Agent Setup

A setup with two agents, each optimized for different work:

Quick Agent ("chat")Deep Agent ("deep")
Soul "Fast, concise assistant. Answer directly." (30 words) "Senior engineer. Think step by step. Check your work." (50 words)
Brain Claude Sonnet (standard) or Gemini Flash (budget) Claude Opus (premium)
Skills Minimal — chat only Code execution, web browsing, file editing
Routing WhatsApp (quick questions throughout the day) Telegram (focused deep work sessions)
Cost per message ~$0.001 ~$0.01–0.05

Use the quick agent for 80% of interactions and the deep agent when you need thoroughness. This can reduce monthly cost by 5–10x compared to running everything on premium.

Optimization Checklist

  • Right-size the brain. Start with Standard tier. Only use Premium for tasks that actually need it.
  • Trim the workspace. Keep bootstrap files lean — every word in SOUL.md, AGENTS.md, and MEMORY.md costs tokens on every turn.
  • Use daily memory. Move running notes to memory/*.md — they're only loaded on demand, not injected every turn.
  • Disable unused skills. Each skill adds to the system prompt.
  • Keep conversations focused. Start fresh sessions for new topics instead of running 100-message threads.
  • Use multiple agents. Route cheap tasks to cheap brains. Route expensive tasks to smart brains.
  • Use sub-agents. Let the main agent delegate focused tasks — sub-agents use a minimal prompt, saving tokens.
